## 硬件/环境检查清单

在每次测试前确认：

- [ ] 狗充电 > 60%（导航会跑 3-5 分钟）
- [ ] 地面平整，测试区域无松动线缆

- [ ] 控制器在手，准备紧急停止（长按 L1+L2 急停，或 `rostopic pub /cmd_vel geometry_msgs/Twist` 全零）
- [ ] NX 网络通（`ping 192.168.123.18` 有回应）

## 测试场景设计

### 场景 1: 直线走廊 (baseline)

**目的**: 测量空旷环境下的跟踪速度和平滑度，排除避障干扰。

**环境搭建**:
- 找一条长 ≥ 5m 的走廊或空旷区域
- 无障碍物
- 起点到终点约 4-6m

**操作步骤**:
1. 让狗站在走廊一端（A点）
2. 启动前端 + 方案 C/B（见上）
3. 发目标点到走廊另一端（B点，约 4-5m 前方）
4. 同时开始录制 bag（场景名 `corridor_clear`）
5. 等狗到达目标点，录满 60s 后停
6. **两个方案各跑一次**，保证起点/终点相同

**预期时长**: 60s per run

```bash
bash record_bag.sh corridor_clear manifold 60
bash record_bag.sh corridor_clear vanilla 60
```

---

### 场景 2: 静态障碍物绕障

**目的**: 测量 DUNE 神经 SDF 效果，比较 vanilla vs manifold 的单圈绕障能力。

**环境搭建**:
- 在走廊/空地放 2-3 个箱子（每个约 0.3×0.3m），随机摆放在直线路径上
- 障碍物间隔约 0.5-1m，让路径有多个绕障点
- 留足通道宽度（≥ 0.7m，约等于狗体宽）

**操作步骤**:
1. 布置障碍物
2. 启动系统
3. 发终点（箱子的另一端，约 4m）
4. 录 90s（狗需要绕障，过程较慢）

```bash
bash record_bag.sh static_obs manifold 90
bash record_bag.sh static_obs vanilla 90
```

**重点观测**: `/cmd_vel` 轮廓（是否有急停急转）、最终是否成功绕过。

---

### 场景 3: 动态障碍物 (人行走穿越)

**目的**: 测量动态环境响应，fake360 obstacle memory 增量效果。

**需要配合人员 1 名**。

**环境搭建**:
- 空旷区域，终点在 3-4m 前方
- 测试人员从侧面横穿狗的行进路径

**操作步骤**:
1. 狗导航出发
2. 测试人员在狗行进到约 1-2m 时横穿（步行速度，不要跑）
3. 穿越后继续让狗到达终点
4. 录 90s

```bash
bash record_bag.sh dynamic_person manifold 90
bash record_bag.sh dynamic_person vanilla 90
```

**重点观测**: 
- 方案 C: 是否触发 stuck-escape，有没有 `/neupan/arrive` 早期 replan
- 方案 B: 是否能在没有 stuck-escape 的情况下绕行

---

### 场景 4: 窄通道 (可选, 难度较高)

**目的**: 测量低净空通道下的控制精度和碰撞阈值。

**环境搭建**:
- 两侧各放一个箱子，中间宽度约 0.75-0.8m（狗体宽 0.35m，两侧各留约 0.2m 余量）

**操作步骤**: 同上，发目标点到通道对面。

```bash
bash record_bag.sh narrow_passage manifold 90
bash record_bag.sh narrow_passage vanilla 90
```

> ⚠️ **安全提示**: 此场景请在手持控制器时执行，随时准备急停。

## 结果提取 (提取指标)

录好 bag 后，下列 `rostopic echo` 或 Python 脚本可以提取对比量：

### 1. 命令速度统计

```bash
# 从 bag 提取 /cmd_vel 数据
rosbag filter corridor_manifold.bag /tmp/vel.bag "topic == '/cmd_vel'"
rostopic echo -b /tmp/vel.bag /cmd_vel | grep "linear\|angular"
```

或用 Python 脚本（后续写）提取以下量：
- 平均线速度 `v_mean`
- 速度标准差 `v_std`（越小越平滑）
- 角速度均值 `w_mean`
- 停顿次数（`v < 0.05` 持续 > 0.3s 的次数）
- 总用时（从目标点发出到 `/neupan/arrive` 或速度趋零）

### 2. 障碍物最近距离

```bash
# 从 bag 提取 /scan_360 的最小 range
rosbag play bag_file.bag &
rostopic echo /scan_360 | grep -E "range_min|ranges" | head
```

### 3. 路径效率

比较 `/odin1/odometry` 的实际轨迹长度 vs 直线起终点距离。

### 4. 快速可视化 (播放 bag + RViz)

```bash
# 播放
rosbag play ~/bags/20260612_161700_corridor_manifold.bag --clock -r 1.0

# 另一终端 RViz (打开 /scan_360 / /neupan_plan / /cmd_vel / /tf 等)
rviz
```

## 常见问题

**Q: 狗一动不动**  
A: 检查 `/initial_path` 是否有数据 (`rostopic echo /initial_path | head`). 如果没有，map_planner 没有收到 goal，检查目标点 topic 是否对（方案 B 用 `/move_base_simple/goal`，方案 C 用 `/neupan/goal`）。

**Q: NeuPAN 节点报 DUNE load error**  
A: 检查 checkpoint 路径 `/home/unitree/code/NeuPAN-vanilla/algo/example/dune_train/model/go2/model_5000.pth` 是否存在。

**Q: 方案 B 节点报 rospy.init_node failed / no master**  
A: 前端 (whole.launch) 没起或 ROS master 没启。先在 Terminal 1 起前端。

**Q: cmd_vel 有值但狗不动**  
A: unitree_control 节点是否运行，`rostopic echo /cmd_vel` 检查是否有连续数据流出。

**Q: bag 录制后不完整 / topic 缺失**  
A: 用 `rosbag info xxx.bag` 检查 topic 列表。如果某 topic 缺失，说明录制时对应节点没发数据（正常情况，比如 `/neupan/arrive` 在 vanilla 方案下永远不会出现）。
